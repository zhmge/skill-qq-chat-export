# NTQQ 本地库格式

写解析器、扩展消息类型、或排查「为什么读不出内容」时读本文件。
列名全是数字字符串，**SQL 里必须加双引号** —— 不加会被 SQLite 当成整数常量
（`select min(40050)` 会静默返回 40050 这个数字本身）。

## 文件布局

```text
偏移 0    ── 1024 字节自定义头
             前 16 字节伪装成 "SQLite format 3\0"，但真正的 SQLite 头
             不在这里；内部含 ASCII 标记 "QQ_NT DB" 与版本号
偏移 1024 ── 标准 SQLCipher 4 内容（4096 字节/页）
```

因此**直接用 SQLCipher 打开原始文件必然失败**，必须先剥掉前 1024 字节。
`scripts/ntdb.py` 的 `usable_db()` 自动判断并剥离。

## SQLCipher 参数

顺序敏感：`page_size` 必须在 `key` 之前设置。

```sql
PRAGMA cipher_page_size = 4096;
PRAGMA key = '<16 位密钥>';          -- 密钥是 16 字节 ASCII 口令
PRAGMA kdf_iter = 4000;
PRAGMA cipher_hmac_algorithm = HMAC_SHA1;
PRAGMA cipher_kdf_algorithm = PBKDF2_HMAC_SHA512;
```

密钥特征：16 位可打印 ASCII。同一账号下**所有** `nt_db/*.db` 共用同一密钥，
且不随 QQ 重启变化 —— 取一次即可解全部。

## nt_msg.db

| 表 | 内容 |
| --- | --- |
| `group_msg_table` | 群聊消息（本 skill 的主要目标） |
| `c2c_msg_table` | 私聊消息 |
| `group_at_me_msg` | @ 我的消息索引 |
| `nt_uid_mapping_table` | UID ↔ QQ 号映射 |
| `recent_contact_v3_table` | 最近会话 |

### group_msg_table 关键列

| 列 | 含义 |
| --- | --- |
| `40001` | 消息 ID（全局唯一，用于解析引用） |
| `40003` | 会话内序号（同一秒内排序用） |
| `40020` | 发送者 UID（`u_xxxxxxxx` 形式） |
| `40027` | 群号 |
| `40030` | 群号（与 40027 同值，冗余） |
| `40033` | 发送者 QQ 号（系统消息为 0） |
| `40050` | Unix 秒时间戳 |
| `40090` | 群名片（可能为空） |
| `40093` | 昵称（可能为空） |
| `40800` | 消息体 protobuf（见下） |

展示名优先取群成员表，其次 `40090`，再次 `40093`，最后回退成 `QQ<号>`。

## 消息体 40800

根消息内 repeated 的 `40800` 字段即**元素**，元素内：

| 元素字段 | 含义 |
| --- | --- |
| `45002` | 元素类型 |
| `45003` | 子类型（灰条等类型用它区分形态） |

### 元素类型对照

| type | 内容 | 取文本的字段 |
| --- | --- | --- |
| 1 | 文本 | `45101` |
| 2 | 图片 | `45815` 摘要（`[图片]`/`[动画表情]`）、`45402` 文件名 |
| 3 | 文件 | `45402` 文件名、`45405` 字节数 |
| 4 | 语音 | `45402` 文件名、`45906` 时长（秒） |
| 5 | 视频 | `45402` 文件名 |
| 6 | 表情 | `47602`（已是 `[流泪]` 这种文本形式） |
| 7 | 回复/引用 | `47422` 被引消息 ID、`47403` 被引者 QQ、`47404` 时间 |
| 8 | 灰条（系统） | 见下 |
| 9 | 互动消息 | 无稳定文本 |
| 10 | 小程序 / ark 卡片 | `47901` JSON，取 `.prompt` |
| 11 | 商城表情 / 表情包 | `80900` 名字 |
| 14 | 闪传 | `48705` 文件名 |
| 16 | 合并转发（聊天记录） | `48602` XML，取 `brief="…"` |
| 17 | 未明确 | — |
| 21 | 通话 | `48153` 文案 |

### 灰条（type 8）的三种形态

按 `45003` 区分，文案**不保证落库**，拿不到就降级成 `[系统消息]`：

- `45003=17` 拍一拍：`48271` 是 JSON，`items[]` 里 `type=qq` 是人（含 `uid`，
  名字可能为空需查成员表）、`type=nor` 是动作文本，拼起来即「A 揉了揉 B 的脸」。
- `45003=4` 戳一戳：`48504` 甲 + `48507` 乙。
- `45003=1` 撤回/入群等：`47713` 为文案，实测大量为空 —— 只能给占位符。

`47713` 有值时的通用形态是 `47705`（人）+ `47713`（文本）。

### 引用（type 7）的还原方法

库里只存了被引消息的 ID，**不存被引正文**。要还原得回到同一个群的消息里按
`40001` 反查并解析其正文。注意：被引消息可能早于本次导出范围，甚至早于本地
留存，查不到就只显示人名。

## group_info.db

| 表 | 关键列 |
| --- | --- |
| `group_list` | `60001` 群号、`60007` 群名 |
| `group_member3` | `60001` 群号、`1000` 成员 UID、`1002` 成员 QQ 号、`64003` 群名片、`20002` 昵称 |

## 已知缺口（数据本身没有，不是解析失败）

- 撤回提示的文案常为空。
- 未同步到本机的历史消息不存在于库中。
- 「已删除的好友/退群成员」可能不在 `group_member3` 里，名字会回退成 QQ 号。
- 库里的 TEXT 列有时以 `bytes` 返回、有时以 `str` 返回 —— 解码函数两种都要兼容。
