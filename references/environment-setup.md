# 环境与依赖

## 需要哪个环境

本 skill 的脚本需要名为 **`skill-qq-chat-export`** 的 Python 环境，
**Python 3.11**。

为什么锁 3.11：SQLCipher 的 Python 绑定在 Windows 上没有通用 wheel，
PyPI 上可用的预编译轮子**只发布 cp311**。换解释器版本会退化成源码编译
（需要 MSVC + SQLCipher 源码），不建议。

环境的**实际位置不写在本仓库里**，由使用者的环境登记表承载。文档与脚本里的
解释器一律用 `<python>` 占位符；解析不了就停下来问，不要拿系统默认解释器硬上。

## 依赖清单

见 [`../scripts/requirements.txt`](../scripts/requirements.txt)。就一个包：

| 包 | 用途 |
| --- | --- |
| `rotki-pysqlcipher3` | SQLCipher 的 Python DBAPI2 绑定（`from pysqlcipher3 import dbapi2`） |

其余全部是 Python 标准库（`ctypes` 读进程内存、`sqlite3` 读解密后的库、
`multiprocessing` 并行校验密钥），**不需要额外安装**。

脚本自身**不写死任何本机路径**：数据目录、工作目录、输出目录、密钥
分别由命令行参数与环境变量传入，所以本仓库可公开、可移植。

## 环境变量

| 变量 | 用途 | 未设时的行为 |
| --- | --- | --- |
| `QQ_DB_KEY` | 数据库密钥（16 位 ASCII） | `decrypt_db.py` 报错并给指引，**不会**去猜、不会读历史文件 |

## 外部依赖（本仓库不含）

| 依赖 | 缺失后果 | 说明 |
| --- | --- | --- |
| 运行中的 NTQQ 桌面客户端（已登录） | **无法提取密钥** —— 密钥只存在于进程内存里，任何文件都不含 | 这是硬前提，没有替代路径 |
| `skill-qq-chat-export` 环境 | 全部脚本无法运行 | 按本文件与使用者的环境登记表创建 |
| 本地已同步的聊天记录 | 导出的时间范围受限于本地留存 | QQ 只把部分历史同步到本地 |

## 单独 clone 本 skill 时的行为

- 缺环境 → 脚本以「找不到解释器 / 模块导入失败」终止。**这是预期行为**，
  按上面的说明创建环境即可，不要把依赖装进系统 Python 或 base 环境。
- 缺 QQ 客户端 → `scan_key.py` 明确报「没有找到进程」。**不要尝试用其它方式拿密钥。**
- 本 skill 不假定任何仓库外的私有上下文存在；需要的信息若不在仓库里，问使用者。
